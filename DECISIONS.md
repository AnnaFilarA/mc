## 2026-10-16 21:00 · оркестратор · src/contracts.py
Вопрос: SPEC 3.3 не описывает входную карточку и формат обмена между этапами.
Решение: `Card(product_id, title, description, seller_attributes: dict[str,str], category_hint)`; `Candidate(attribute, raw_value, value, unit, score, stage, evidence)`.
Evidence для `seller_attributes` указывает на строку `seller_attributes_text()` — «ключ: значение» через `\n`.
Инвариант `evidence_is_valid()`: `source_texts(card)[source][start:end] == text` (по сырому тексту, не очищенному).
Почему: нужен единый проверяемый способ доказать, что значение есть в тексте.
Обратимо: да (меняет только оркестратор).

## 2026-10-16 21:00 · оркестратор · канон значений
Вопрос: как выглядит каноническое значение.
Решение: number — строка числа без единицы, точка как разделитель (`"8"`, `"6.67"`), 1 ТБ = `"1024"` GB; единица в `unit` (`GB`, `inch`, `Hz`).
enum — строго из `values` схемы (цвета по-русски с заглавной, `ё→е`).
`unchanged` — если `was` после `strip()`/без учёта регистра равен `value` или `"value unit"` и подтверждён;
значение продавца верное, но в другом виде («8 Гб») → `proposed` (нормализовано).
Почему: простое и проверяемое правило «уже в каноническом виде» (INTENT 2.2).
Обратимо: да.

## 2026-10-16 21:00 · оркестратор · cascade / card_status
Вопрос: SPEC 3.4 — `card_status` считается по всем атрибутам или по обязательным?
Решение: по обязательным (`required: true`); необязательные поля статус карточки не меняют, но в ответе есть.
Почему: иначе любая карточка без, например, частоты обновления ТВ уходит продавцу — лишняя нагрузка.
Обратимо: да.

## 2026-10-16 22:00 · поток E · src/llm.py
Вопрос: как устроен Этап 3 и какие провайдеры поддержаны.
Решение: `HttpLLM` с адаптерами провайдеров (`openai_compatible`, `gigachat` — тот же формат, `yandexgpt` — нативный API); транспорт инъецируется (`transport(url, headers, payload, timeout) -> dict`), по умолчанию httpx. Ключ только `os.environ["LLM_API_KEY"]`. Кандидат LLM: `stage="llm"`, `score=max_score` (0.7, `llm.yaml`), `value` уже в каноне схемы (enum — из справочника, number — число без единицы), `unit` из схемы, `evidence` пересчитана по тексту карточки. Статус `low_confidence` обеспечивает порог proposed 0.80 > 0.7; поле `max_status` в конфиге документирует правило, применяет его каскад (поток B) — поток B не должен поднимать score кандидатов stage=llm выше порога proposed.
Почему: код не зависит от провайдера (SPEC 6.2), тесты без сети, значение без цитаты в тексте отбрасывается (SPEC 8.1).
Обратимо: да (`config/llm.yaml`, `_ADAPTERS` в `src/llm.py`).

## 2026-10-16 22:00 · поток E · src/llm.py (кэш, лимит, повторы)
Вопрос: что считать вызовом, что кэшировать, сколько повторов.
Решение: `calls` растёт на каждый реальный HTTP-запрос (включая единственный повтор при невалидном JSON); попадание в кэш `calls` не меняет. Кэш — JSONL `cache_path`, ключ sha256(model + полный промпт), хранятся только валидные JSON-объекты. Лимит `max_calls_per_run` исчерпан → пустой результат без запроса. Сетевая/HTTP-ошибка → пустой результат без исключения и без повтора. Для `complete_json` используется `schema_bootstrap.model` из конфига (если задана), для `resolve` — `model`.
Почему: INTENT 7 (кэш, лимит, не тратить деньги зря); каскад не должен падать из-за LLM.
Обратимо: да.

## 2026-10-16 22:00 · поток E · src/schema_bootstrap.py
Вопрос: формат черновика, очередь, поведение без LLM.
Решение: `bootstrap_schema(cards, category, llm=None, click_stats=None, min_cards=None)`: меньше `min_cards` (по умолчанию 20 из `llm.yaml`) → ValueError. Ответ LLM валидируется в формат схемы категории (код — snake_case латиницей, enum без справочника понижается до text, до 12 атрибутов); при NullLLM/без LLM/невалидном ответе — эвристика (частые слова title, brand/color), `draft_source: heuristic`. В черновике есть служебные ключи верхнего уровня `draft_source` и `source_cards` — загрузчик утверждённых схем (`prepare.load_schemas`, поток B) должен игнорировать неизвестные ключи верхнего уровня (или менеджер удаляет их при утверждении). `save_draft` пишет только `<category>.draft.yaml`, код категории ограничен `[a-z0-9_]`. Очередь `NewCategoryQueue` (`data/new_category_queue.jsonl`, строка = `{category, ts, card}`, повторы по product_id схлопываются); API для потока C/B: `add(category, card)`, `count`, `counts`, `ready(category, n=None)`, `cards(category)`. CLI: `python -m src.schema_bootstrap --queue ... --category ...` (`--list` показывает накопление).
Почему: INTENT 4.2, SPEC F15; маршрут работает без ключа.
Обратимо: да.

## 2026-10-16 22:00 · поток E · как включить реальный LLM
Решение: в `config/llm.yaml` выставить `enabled: true`, `provider`, `model` (и `base_url` для openai_compatible, `folder_id` для yandexgpt), затем `export LLM_API_KEY=...`. Без ключа или при ошибке конфига `load_llm` возвращает NullLLM с записью в лог. Реальные платные вызовы в тестах и разработке не делались (SPEC 8.3).
Обратимо: да.
