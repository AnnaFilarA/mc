# Задача агенту-оркестратору (вставить в Claude Code целиком)

> Модель: **Claude Opus** для этой сессии (оркестратор). Подагентам — **Sonnet**, массовым простым задачам — **Haiku**.

---

Ты — ведущий инженер и оркестратор проекта **AttrGuard** (хакатон «Точка сборки», кейс М.Видео «ИИ для автоматического заполнения характеристик товаров»). Команда — «Все из ничего». Срок — **1–2 дня**. Главный принцип — **минимум затрат времени и денег**.

## Шаг 1. Прочитай и подтверди понимание
1. Прочитай `INTENT.md`, затем `SPEC.md` полностью. Порядок приоритета документов — в SPEC, раздел 1.
2. Перескажи в 10–15 строках:
   - что строим и зачем;
   - что считается готовым результатом;
   - три вещи, которые нельзя нарушать: нет значения без evidence; LLM по умолчанию выключена и только для спорных полей; на test-выборке ничего не настраиваем.
3. Выпиши, что тебе непонятно или противоречит друг другу. Если есть вопрос, который блокирует фазу 0, — задай его мне и жди. Остальное — реши сам и запиши в `DECISIONS.md`.

## Шаг 2. Фаза 0 — каркас (делаешь сам, последовательно)
1. Создай структуру репозитория из SPEC 3.2: пустые модули с сигнатурами, `requirements.txt`, `README.md` (черновик), `DECISIONS.md`, `BACKLOG.md`, `config/`, `data/`, `tests/`.
2. Напиши `src/contracts.py` строго по SPEC 3.3. **Это замороженный контракт:** после фазы 0 менять его можешь только ты.
3. Создай 20–30 эталонных карточек в `tests/fixtures/` (смартфоны, ноутбуки и ещё 1–2 категории) с ожидаемыми ответами. Включи трудные случаи: «8/256GB», конфликт цвета, отсутствующее значение, «16 ГБ ОЗУ + 512 ГБ SSD».
4. Создай скиллы из SPEC 7 в `.claude/skills/`: `add-category`, `run-eval`, `add-rule`, `ui-screen`, `log-decision`.
5. Убедись, что `pytest` запускается (тесты на заглушках могут быть помечены `xfail`).
6. Зафиксируй всё одним коммитом «phase 0: skeleton and contract».

## Шаг 3. Фаза 1 — запусти 5 подагентов параллельно
Каждый подагент работает **в отдельном git worktree** и меняет **только свои файлы** (SPEC 3.2). Каждому передай:
- ссылку на INTENT.md и SPEC.md;
- свою зону файлов;
- критерий готовности;
- правило: «нужно изменить чужой файл или контракт → запиши запрос в DECISIONS.md и остановись на этом месте».

| Поток | Модель | Задача | Готово, когда |
|---|---|---|---|
| **A · EDA** | Sonnet | `notebooks/01_eda.ipynb` + `outputs/metrics/eda_summary.md`: поля, форматы, пропуски, размер размеченной части, топ-5 категорий, обязательные поля, распределения и длинный хвост значений, частоты атрибутов в кликах. Сформировать `config/categories/*.yaml` для топ-5 и разбиение train/val/test (по товару, стратифицировано по категориям) | ноутбук выполняется без ошибок, YAML для 5 категорий, файлы разбиения сохранены |
| **B · Ядро** | Sonnet | `prepare.py`, `rules.py`, `normalize.py`, `cascade.py` по SPEC 3.4–3.5 (Этап 1 + статусы + вопрос продавцу) | все фикстуры проходят; ни одного `proposed` без evidence |
| **C · Веб и API** | Sonnet | `api.py` + `web/` по SPEC 4: выбор роли, кабинет менеджера, кабинет продавца, feedback в SQLite. Работает на фикстурах, если ядро ещё не готово | оба сценария из SPEC 4.5 проходят вручную в браузере |
| **D · Оценка** | Sonnet | `evaluate.py`: P/R/F1 и coverage по атрибутам и категориям, F1 с весом по трафику, сравнение конфигураций, `threshold_cost` по формуле INTENT 5.2 | на фикстурах выдаёт все файлы из SPEC 2.3 |
| **E · LLM и новые категории** | Sonnet | `llm.py` (`LLMClient`, `NullLLM`, `HttpLLM`, кэш, лимит вызовов, проверка цитат), `schema_bootstrap.py`, `config/llm.yaml` | с `NullLLM` пайплайн работает; `HttpLLM` проверен на мок-ответе |

Массовую генерацию синонимов и словарей поток A и B отдают подагенту на **Haiku**.

Пока потоки работают:
- раз в итерацию читай `DECISIONS.md` и отвечай на запросы по контракту;
- ничего не меняй в их файлах сам.

## Шаг 4. Фаза 2 — интеграция (сам, последовательно)
1. Слей потоки A–E в основную ветку. Конфликты решай по владельцу файла.
2. Запусти `python -m src.pipeline` на реальных данных (конфигурация «только правила»).
3. Запусти `run-eval`. Получи `predictions.jsonl/csv` и `per_attribute.csv`.
4. **Покажи мне результат и короткий отчёт:** что работает, худшие 5 атрибутов, время на карточку. Это минимальный сдаваемый результат — дальше идём только после него.
